## 2. 架构总览

```
┌─ WorkManager（每日 15:30，系统调度）────────────────────────┐
│                                                             │
│  ⓪守卫：交易日判断 + 幂等检查（今日已跑？）                  │
│       ↓                                                     │
│  ①后台 Service 起 headless WebView（无界面）                 │
│       ↓                                                     │
│  ②增量拉取（updateKlineIncremental，仅白名单合约 × 所需周期）│
│       ↓                                                     │
│  ③引擎【全量重跑】主策略（A 模式，确定性、可复现）         │
│       ↓                                                     │
│  ③b 前向观察策略（最多 3 个，沙盒账户，同步跑、只记录）      │
│       ↓                                                     │
│  ④排序成交（单账户；同刻多品种按品种 ID 稳定排序）           │
│       ↓                                                     │
│  ⑤AI 提意见（当天信号合并为一条；**仅记录，不参与决策**）    │
│       ↓                                                     │
│  ⑥算当日盈亏（含浮动盈亏）→ 落盘（主账户+沙盒+权益+日志）    │
│       ↓                                                     │
│  ⑦NotificationManager 通知（成功/失败/非交易日/资金不足）    │
└─────────────────────────────────────────────────────────────┘

失败任意一步 → 通知写明"哪一步失败 + 今日未执行"，绝不出 0.00 假装正常
```

> **③b 说明**：前向观察策略与主策略**在同一 WorkManager 任务、同一份数据上同步跑**，
> 但走**独立沙盒账户**，只记录、不碰主账户（详见 §4b.2）。

### 2.1 为什么是手机本地，不是服务器

| 理由 | 依据 |
|---|---|
| 通知必须由 App 自己弹 | 云端无法唤醒 App（国内 FCM 不可用；Android 9+ 禁明文 HTTP；自建需备案+证书） |
| 云端叫不醒未注册后台调度的 App | Android 硬约束 |
| AI 不在拉取链路上 | `screener → webdata → Android.httpGet → HttpURLConnection`，桥由 Java 侧 `addJavascriptInterface` 挂载，与界面无关 |
| 策略在手机、引擎在手机 | 无"策略同步"问题 |

### 2.2 决策链完全确定（关键）

```
AI 已从"拍板"退到"只提意见"  →  决策链 = 纯引擎规则  →  系统完全确定性
    ↓
A 模式全量重跑可用  →  可复现  →  验收第 6 条天然成立
```

## 3. 职责分层

```
第1层 引擎（确定性）    跑主人的策略 → 产生信号        可回测、可复现、免费
第2层 AI（只提意见）    看信号与行情 → 评分/理由/倾向    **不参与决策**；失败静默降级
第3层 账本（唯一事实）   持仓/成交/权益（单账户）        每天落盘
```

**铁律**：
- 引擎与账本**绝不依赖 AI 在线**
- **AI 不参与决策** —— 买不买由引擎规则决定，AI 只输出意见（可被主人日后参考）
- 每笔成交存 **`signal`（引擎原始）** 与 **`opinionRef`（AI 意见定位键）** → 保留归因能力
  > ⚠️ 字段名统一为 **`opinion`**（不是 `decision`）—— AI 已降级为"只提意见"，用 `decision` 会误导为"AI 在拍板"。
- **AI 的每次意见都落盘**（含 `verdict:'skip'` 时）→ 可回答"AI 错过/避免了什么"
  > ⚠️ **AI 意见存放在日志 `ai.opinions[]`，不在 `trades` 里** —— 因为 AI 说"别买"时没有成交，
  > 挂在成交上会永久丢失。详见 §6.1。
- **AI 每天最多调一次**：当天所有信号**合并成一条 prompt**，一次拿回全部意见（省成本、日志干净）

### 4b. 试算与观察（保留能力，全部沙盒化）

**已有实现（复用，不重写）**：
- 「策略对比」页：跑同一合约/周期出指标表（收益/胜率/回撤/盈亏比/夏普/交易数），标出每项最优 —— **只读本地 K 线缓存，回测是纯函数，干净** ✅
- 「对比模拟」：把结果画到 K 线上

**数据复用（已成立）**：两者都读本地 K 线缓存，**不重新拉网**。

**⚠️ 必须修的坑**：
```js
views/sim.js:158  acc = r.account;    // 按策略执行 → 覆盖主账户
views/sim.js:253  acc = r.account;    // 试算结果画到K线 → 覆盖主账户（污染源）
```
试算必须走**独立沙盒账户**，**绝不写回主账户**。

---

#### 4b.1 回放试算（样本内 · 快 · 不可信）

跑已有的「策略对比」即得，秒级出结果。

> **强制标注**：`⚠️ 样本内回放 · 仅用于筛出逻辑错误，不作优劣结论`

**为什么不可信**：那段数据主策略已经跑过、主人也已经看过结果 → 对观察策略而言是"已知答案"的数据。
**在已知答案的数据上挑策略 = 过拟合。数据真实 ≠ 没有偷看答案。**

#### 4b.2 前向观察（样本外 · 慢 · 唯一可信）

```
主策略 A  → 真下单，主账户（5 万）
观察策略 B → 沙盒账户，只记录信号与理论盈亏，不碰主账户
    ↓
B 从今天起跟着每天的新数据往前走（前向 / paper trading）
    ↓
今天买没买、明天赚没赚 —— 事先谁都不知道
    ↓
攒够 30 笔才有结论
```

- **观察位数量**：默认 **最多 3 个**，**可配置、不写死**（主人可自行增减）
- **策略可编辑**：观察策略的代码主人可随时修改（改后**计数器重置**，之前累积的笔数作废——避免新旧逻辑混算）
- **不与"单策略"冲突**：无串行、无裁决、不影响主账户；**只是给 B 开一个影子账本**
- 与 §4#14 的试运行段（10-30 笔固定 1 手）互为载体

#### 4b.3 两者分工

| | 回放试算 | 前向观察 |
|---|---|---|
| 速度 | 秒级 | 数周~数月 |
| 结论 | ❌ 会骗你（样本内） | ✅ 可信（样本外） |
| 用途 | 筛掉逻辑写错的 | 判断真行不行 |

## 5. 新增原生件（4 件）

### 5.1 文件桥（替代 K 线 localStorage）

```
Android.fsWrite(path, text)        // 写文件，返回 __OK__ / __ERR__xxx
Android.fsRead(path)               // 读文件，不存在返回 __ERR__NOTFOUND
Android.fsList(dir)                // 列目录，JSON 数组
Android.fsDelete(path)             // 删除
```

- 实现：`java.io.File` + `getFilesDir()`，**零依赖、免权限**
- 目录：`files/kline/`、`files/account/`、`files/log/`
- 首次启动**必须迁移** localStorage 里的 K 线（不能靠重拉）

### 5.2 WorkManager Worker

- 起 headless WebView（**主线程初始化**）→ `evaluateJavascript` 跑引擎内核
- **不可跑 `views/*`**（`document.getElementById` 在 headless 下返回 `null` 会炸）
- 可跑内核：`indicators` / `screener` / `backtest` / `sim` / `strategy-runner`
  - `sim.js`：0 处 localStorage ✅
  - `screener.js`：11 处需适配 ⚠️

### 5.3 通知（三件套，缺一静默丢失）

```xml
① Manifest 声明 POST_NOTIFICATIONS
② Android 13+ 运行时申请
③ Android 8+ 建 NotificationChannel
```

### 5.4 交易日判断

**方案：静态表为主 + 接口为辅**（实测依据见 §15 附注）

- **主**：静态节假日表（2003-2026，来源参考 MIT 许可的 `shinnytech/shinny-calendar`）
- **辅**：每年拉一次接口补新假日；**失败则静默降级用旧表**（不让核心功能依赖会限流的服务）
- **推算逻辑（约 30 行）**：
  ```
  交易日 = 从上一交易日 20:00 → 当日 20:00
  若落在 周末 或 节假日 → 顺延到下一个交易日
  ```
- **交易日切换时点：20:00**（夜盘开盘前缓冲；可配置）
- 输出：`交易日 | 非交易日 | 数据未就绪`

## 6. 数据契约

### 6.1 账户对象（落盘）—— **单策略单账户**

```js
{
  // 单策略：账户就这一套，5 万
  initialCash: 50000,
  cash, position, avgPrice, realized, unrealized,
  marks: [],            // 买卖点
  trades: [             // 成交明细（只记"真的成交了"的）
    {
      time, type, price, qty, pnl, commission,
      contract,                                 // 品种（多合约聚合靠它）
      signalType,                               // 信号类型（BUY/SELL/REDUCE/CLOSE）
      signalReason,                             // 引擎原始信号的理由
      opinionRef: { contract, signalType, signalTime }
        // AI 意见的定位键 → 指向日志 ai.opinions[]
        // ⚠️ signalTime = 信号**产生**的时间（不是成交时间）；
        //    信号在第 N 根产生、可能第 N+1 根才成交，两者不同，必须用信号时间才能查到。
    }
  ],
  equity: [],           // 每日权益快照（当日盈亏的基准）
  ctxState: {},         // 策略持久状态（连亏计数/暂停方向）
  blowups: 0,           // 爆仓累计次数（重置不清零）
  lastRunDate,          // 幂等键（防重复通知）
  status: 'active' | 'paused' | 'blown'
}
```

> **⚠️ AI 意见不放在 `trades` 里**（关键修正）：
> AI 的意见是对**信号**给的，不是对成交给的。若 AI 说 `verdict:'skip'`（别买），
> **那就没有成交、这笔记录根本不存在** → AI 那句"别买"就永久丢失，
> 与 §3 铁律「AI 的每次意见都落盘（含 skip）」直接冲突。
>
> **正确落点**：AI 意见存在**日志的 `ai.opinions[]`**（以 `contract + signalType + time` 为键），
> 覆盖当天**全部信号**（无论后来成交与否）。`trades` 里只留一个 `opinionRef` 便于回查。

> **说明**：删除多策略后，主账户就这一套策略。
> **多品种聚合**：每笔标 `contract`，当日盈亏既可按品种拆（`byContract`），也可合计。

### 6.1b 沙盒账户（前向观察用，最多 3 个）

```js
// 与主账户同构，但独立存储、只记录、不参与主账户资金
{
  watchId: 'w1' | 'w2' | 'w3',
  name,                 // 主人自定义
  code: '',             // 观察策略代码（主人可随时改）
  initialCash: 50000,   // 与主账户同额，便于对比
  cash, position, avgPrice, realized, unrealized,
  trades: [ { time, type, price, qty, pnl, commission,
              contract, signalType, signalReason } ],   // 无 opinion（观察策略不提意见）
  equity: [],           // 每日权益快照
  tradeCount,           // 累积笔数（改策略代码 → 重置为 0）
  ctxState: {},
  status: 'observing' | 'graduated' | 'rejected'
}
```

> **关键**：沙盒账户**绝不写回主账户**；改 `code` 时 `tradeCount` 与 `trades` **重置**
> （避免新旧逻辑混算）。满 30 笔后由主人决定是否"升级"为主策略。

### 6.2 日志（每日一条，全量）

```js
{
  tradeDate,
  steps: {
    guard:  { ok, isTradingDay, alreadyRan, err },
    fetch:  { ok, added, updated, total, err },
    engine: { ok, signals: [                              // 当天全部信号（含未成交的）
                { contract, signalType, time, reason }
              ],
              executed: [],                               // 实际成交的信号（含成交价/手数）
              skipped: [                                  // 有信号但未成交
                { contract, signalType,
                  reason: 'insufficient_funds'            // 资金/保证金不够
                        | 'ranked_out' }                  // 同刻多品种，排序靠后
              ], err },
    watch:  { ok, accounts: [                            // 前向观察的每日推进
                { watchId, tradeCount, dayPnl, err }
              ], err },
    ai:     { ok, called, combined: true, opinions: [     // 当天信号合并一次；覆盖全部信号
                { contract, signalType, time,             // ← 与 engine.signals 同键，含未成交的
                  verdict: 'buy'|'skip', score, reason }  // ← AI 意见（非决策）
              ], err },
    pnl:    { ok, equity, realized, unrealized, dayPnl, byContract: {} }
  },
  klineTime,            // 决策输入的 K 线时间
  finishedAt,
  result: 'success' | 'failed' | 'non-trading-day' | 'data-not-ready'
}
```

## 7. 运行时规则

### 7.1 硬要求（A 模式，已从 B 的 4 条减到 1 条）

| # | 要求 | 不做的后果 |
|---|---|---|
| 1 | **指标预热窗口**（喂足 ≥26 根 4H） | 只喂新增 K 线 → 指标算错 → **信号全错** |

> **B 模式原有的另外 3 条已消失**（状态严格落盘 / 幂等 / 失败续跑）——
> A 模式每次从历史起点重跑，天然无状态残留。但**幂等守卫仍保留**（§2⓪，防重复通知）。

### 7.2 资金与风控

**初始资金 5 万。** 风险模式门槛实算（`手数 = floor(资金 × 0.5% ÷ (ATR × 乘数))`）：

| 品种 | 乘数 | 典型 ATR | 风险模式诚实所需本金 |
|---|---|---|---|
| 玉米 | 10 | 8~20 点 | 1.6 万 ~ 4 万 |
| 豆粕 | 10 | 15~35 点 | 3.0 万 ~ 7 万 |
| 螺纹钢 | 10 | 17~40 点 | 3.4 万 ~ 8 万 |
| 纯碱 | 20 | 20~50 点 | 8 万 ~ 20 万 |
| 铁矿 | 100 | 10~25 点 | 20 万 ~ 50 万 |

> ✅ **已定（由策略本身决定，不硬编码）**：止损距离 = **1.5 × ATR14**，来自策略模板
> `strategy-templates.js:135` 的 `stopAtrMult: 1.5`（第 233/237 行 `ctx.stopLoss = close1 ∓ P.stopAtrMult * a14`）。
> 引擎 `sim.js:73 calcSizeByRisk(cash, spec, entryPrice, stopPrice)` 用的是**策略传入的 `ctx.stopLoss`**，
> 不是固定倍数 —— 即"按策略来"在实现上本已成立。**任何策略改自己的 `stopAtrMult`，手数自动跟着变。**

**品种白名单（据此自动筛出，无需另定规则）**：
`1.5 × ATR × 乘数 ≤ 资金 × 0.5%` 且理论手数 ≥ 1。5 万下实测：

| 品种 | 1.5×ATR 每手止损 | 5 万下实际风险 | 判定 |
|---|---|---|---|
| 玉米 | 180 元 | 0.36%（0.7×） | ✅ |
| 螺纹钢 | 285 元 | 0.57%（1.1×） | ✅ |
| PTA | 300 元 | 0.60%（1.2×） | ✅ |
| 豆粕 | 330 元 | 0.66%（1.3×） | ✅ |
| 纯碱 | 900 元 | 1.80%（3.6×） | ❌ 排除 |
| 铁矿 | 1800 元 | 3.60%（7.2×） | ❌ 排除 |

> 对比 1 万本金：**全部品种不可用**（螺纹钢 2.85%/5.7×，铁矿 18%/36×）。→ **5 万的选型得到验证。**

**强平**（已同意加）：
- 线：**维持保证金 = 保证金率的一半**（螺纹钢 7% → 3.5%）
- 触发：权益 ≤ 维持保证金要求 → 强平，`status='blown'`，`blowups += 1`
- 后果：**该策略自动 `paused`**，直到主人重置

**爆仓计数**：**保留累计，重置不清零**（用于回答"这套策略到底行不行"）

**重置按钮**：只重置金额（回 `initialCash`），**不重置爆仓次数**

**单策略 × 多品种调度（只有排序，没有裁决）**：

```
每天对 白名单品种 逐个全量重跑（同一套策略）
        ↓
收集各品种的"开仓"信号
        ↓
同一时间多品种同时出信号 → 按资金/保证金先后成交（先到先得，按品种 ID 稳定排序）
        ↓
其余记为 skipped，写入日志 engine.skipped，并标原因：
        · insufficient_funds —— 资金/保证金不够（对应 §9 通知"资金不足"）
        · ranked_out        —— 同刻多品种，排序靠后
        ↓
持仓期间按策略自身逻辑（REDUCE / CLOSE / 硬止损）
```

> ⚠️ **术语**：单策略下**没有"裁决"**（那是已删除的多策略时代产物：ATR 占比裁决）。
> 这里只有**排序成交**——同一套策略的信号之间不存在竞争，只是资金不够时按固定顺序成交。

- **单账户**：就这一套策略，5 万
- **每笔成交标 `contract`** → 可按品种聚合
- **当日盈亏**：账户总权益差（`权益今天 − 权益昨天`）；**同时给出按品种拆分**（`byContract`）

### 7.3 交易时段

```
一个交易日 = 上一交易日 20:00 → 当日 20:00（切换点 20:00，可配置）
夜盘归属下一交易日；周五夜盘归下周一
```

- **切换时点 20:00**（夜盘开盘前缓冲；与开源实现一致）
- 非交易日 → 通知"**今日非交易日，未执行**"（不报失败、不出 0.00）
- 收盘价 ≠ 结算价 → 报告标注"**理论盈亏**"
- 数据延迟 → 15:30 可能拿半截；建议容忍或后移

### 7.4 换月

- 适应阶段继续用主连
- **报告标注"含换月跳空失真"**
- **换月日在 K 线上打标记**（让失真可见，不隐形）
- 实盘前必须补"**主连 → 具体合约**"映射层（如 `rbm` → `rb2605`）

## 8. 判断规则

```
① 门槛（唯一判断）：这套策略行不行 = 全部满足
        · 交易笔数 ≥30（10-30 为试运行段，只标注不下结论）
        · 最大回撤 ≤20%
        · 盈亏比 ≥1.2
        · 胜率 ≥40%
② 复评：每月一次；连续 2 个月不达标 → 提示停用
③ 预警：每天只看危险线（回撤突然翻倍 / 连亏 5 笔）
```

> **删除多策略后**：原"排序（综合分）"与"裁决（ATR 占比）"**全部消失**——
> 单策略没有竞争者，不需要排名与取舍。只剩"这套策略过不过门槛"。

**样本门槛为什么是 30**（实算）：

| 笔数 | 观测胜率 60% 的 95% 置信区间 |
|---|---|
| 10 笔 | [31.3%, 83.2%] ← **下界 31%，判不出好坏** |
| 30 笔 | [42.3%, 75.4%] |
| 100 笔 | [50.2%, 69.1%] |

> 真实胜率 50%（纯运气）时，10 笔里出现 6 胜的概率约 **37%**。

## 10. 验收标准

1. 设好 15:30 后，**不打开 App** 能自动跑完一轮
2. 成功 / 失败，**通知栏都有一条**，点开看得到当天盈亏
3. 通知含**盈亏 + 信号 + 两个评分**（**行情评分** + **主策略**评分，分开标注；观察策略评分不进通知）
4. **失败写明哪一步** —— 六步全覆盖：**守卫 / 拉数 / 引擎 / 观察 / AI / 通知**，不是一句"失败了"
   > 注：AI 失败属"不算失败"（见 §9），但**仍须在通知里标明发生**，便于排查
5. **非交易日写"今日非交易日，未执行"** —— 既不报失败，也不出 0.00
6. **连跑 7 天，数字与手动跑一遍完全一致**（A 模式可复现，此条成立）
   > **"手动跑一遍"的口径**：白名单品种**逐个各跑一次**，再把各品种盈亏**相加**；
   > 与自动跑的账户总权益差比对（也允许按 `byContract` 逐品种比对）。
   > 注意：现在 App 的「模拟盘」是**单合约**账户，不支持多品种合账，所以此条须在实现阶段 5 一并补上对照方式。
7. **失败时绝不出 0.00 假装正常**
8. **资金不足与系统故障在通知里分开**
9. **爆仓计数永久保留，重置后不清零**
10. **同一天重复执行，结果完全一致**（幂等验证；A 模式实测已通过）
11. **首次未授权通知时**，有引导路径可用（否则通知发不出）

> 第 6、7 条针对 README v2.3.0 修过的"缓存写满时假成功"——"看起来在跑其实没跑"是本系统最大失败模式。

## 11. 已知局限（诚实声明）

| 局限 | 影响 |
|---|---|
| WorkManager 不保证准点 | 15:30 可能延到 16:00+，Doze 下更久 |
| 单策略 | 只能看这一套策略表现，无法同屏比较（试算可手动看，见 §4b） |
| 主连换月跳空 | 模拟成绩含失真，报告需标注 |
| 模拟盘无滑点/真实成交 | 模拟赚 ≠ 实盘能赚 |
| 无结算价 | 只能算理论盈亏 |
| 强平后策略暂停 | 归零后需主人重置才能继续验证 |
| 硬止损在逐日推进下的解释 | 引擎按"当前根 high/low"判盘中止损；日线粒度下"盘中"不可分辨，需按日线口径重述 |
| AI 意见不参与决策 | 系统完全确定性，但也失去"AI 救了/躲过一劫"的可能性 |
| 试算为样本内 | 回放结果会过拟合，必须标注"样本内，仅筛逻辑错误"；真结论只能来自前向观察 |
| 前向观察慢 | 攒够 30 笔要数周~数月，急不得 |

## 14. 附注：A vs B 模式实测证据

**方法**：用真实引擎（`strategy-runner.js` + `sim.js` + 真实策略模板）跑基准。

```
单合约全量重跑（1000 根）        :  75 ms
A 模式 白名单 4 品种 × 4 策略    : 464 ms（每天）
B 模式 同规模增量推进            :  16 ms（每天）
绝对差值                          : 448 ms/天
```

**可复现性验证（A 模式）**：

```
同一数据跑两次 → cash=96947.48 / trades=21，两次完全一致 ✅
```

**结论**：B 省下的 448 ms/天，对"每天跑一次"的任务无意义；
A 白拿可复现 + 验收第 6 条成立 + 无需状态落盘。**故选 A。**
